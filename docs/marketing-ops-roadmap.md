# marketing-ops 扩展路线

> 状态：Content Studio 总路线的配套子路线
> 最近评审：2026-08-02

## 定位

`marketing-ops` 是 Content Studio 的独立渠道执行层，也是一个独立的信任边界。
Content Studio 负责项目、发布活动、内容、素材、制作任务和控制面；
`marketing-ops` 负责渠道账号授权、渠道策略、外部写入、发布回执以及授权范围内
的监测读取。

它会随 Content Studio 安装，但不能因为“随附安装”就获得发布权限。两边使用版本化、
有类型的契约连接，凭据、Cookie、浏览器 Profile、支付信息和平台私有会话永远留在
`marketing-ops` 自己的本地边界内。

## 当前事实（不是目标能力）

当前公开 MCP 接口可以确认：

- 调用按稳定 `projectId` 隔离；写入前要先读取该项目的渠道状态。
- `channels_status` 返回脱敏的渠道健康、适配器状态、账号别名和下一步建议。
- 当前公共状态面按渠道暴露一个可见 `alias`；它还不是统一的多账号目录接口。
- `publish_campaign` 的发布包没有 `channelAccountRef`/`accountId` 选择字段。
- 发布回执、报告和反馈接口也没有统一的账号维度。
- 个别适配器内部可能已有账号 ID，但这不等于跨渠道、可由项目选择的公共能力。

因此，“一个渠道多个账号、项目绑定其中几个、活动选择具体账号”目前是
Content Studio 的目标模型和工作台预留，不应被描述成已经可以真实执行的
`marketing-ops` 能力。真正发布仍以 `marketing-ops` 当前项目档案和渠道策略为准。

## 目标边界

```text
Content Studio core / MCP / Vue 控制面
        │  有类型的项目范围客户端
        ├─ 读取新鲜状态和能力
        ├─ 提交 renderer 生成的发布包
        └─ 接收并校验发布回执
        ▼
marketing-ops
        ├─ 项目档案与渠道策略
        ├─ 渠道账号目录和授权状态
        ├─ 自动适配器 / 人工辅助流程
        ├─ 外部写入、幂等和回执
        └─ 公开或授权范围内的监测读取
        ▼
官方渠道
```

Content Studio 可以保存账号引用和脱敏投影，但不能保存或转发账号秘密；
`marketing-ops` 可以拒绝发布、要求重新授权或把任务交给渠道授权人，Content Studio
必须如实显示这些结果。

## 分阶段路线

### M0：契约基线与受控客户端（对应 Content Studio V0.5 起步）

- 固定 `marketing-ops` 兼容版本和 Content Studio 客户端版本矩阵。
- 为 `channels_status`、发布准备、发布提交、状态查询、回执和监测读取建立有类型
  客户端；不在 Vue 中直接拼 MCP 参数。
- 每次写入前执行项目级状态刷新、能力检查、素材校验和授权检查。
- 增加 `dry-run`/`assisted-prepare` 等不产生外部写入的准备阶段。
- 建立本地假适配器和契约测试，测试不连接真实渠道。

验收：渠道未配置时仍能完成 AI 创作和本地制作；发布任务会明确显示“未配置”或
“被阻塞”，不会从 UI 状态推断授权。

### M1：单渠道多账号与项目绑定（优先扩展）

这是解决当前缺口的第一优先级。

- 引入稳定、不透明的 `channelAccountRef`，与平台账号别名分离。
- `channels_status` 返回渠道下的账号列表，每个账号有独立健康、授权、适配器和
  下一步状态。
- 增加项目渠道账号绑定：项目可绑定多个账号、设置默认账号，活动只能选择已绑定
  的账号。
- `publish_campaign`、发布回执、监测快照、报告和反馈都带账号引用。
- 账号共享默认为关闭；跨项目复用必须由 Owner 明确打开并留下审计记录。
- 增加账号的启用、停用、重新授权、健康刷新和脱敏展示；不提供导出秘密的接口。

验收：同一渠道的两个账号可以在两个项目或同一项目的不同活动中被明确区分；
一个账号的授权失败、发布记录和指标不会污染另一个账号。

### M2：发布编排、人工接管与可信回执（对应 V0.5）

- 统一发布包校验：项目、活动、渠道、账号、格式、媒体校验和、内容版本必须匹配。
- 保留 `automatic`、`assisted-prepare`、`assisted-confirm` 三种执行模式的边界。
- 发布前生成明确的人工接管包，渠道授权人在官方页面完成登录、验证码、审核和
  最终点击；系统不接收这些输入。
- 使用稳定活动 ID 和幂等键；状态不确定时先查询，不能盲目重发。
- 只有 `marketing-ops` 持久化的、项目/活动/渠道/账号均匹配的成功回执，才能让
  Content Studio 进入 `published`。
- 回执包含外部地址、内容校验和、账号引用、时间、适配器摘要和可追踪错误码。

验收：重复提交不会造成重复发布；人工完成登录但没有官方回执时，状态仍是等待
确认或未知，不显示“已发布”。

### M3：账号维度的监测与报告（对应 V0.5 后半段）

- 为每条发布记录创建 1 小时、48 小时、7 天或项目自定义的采集计划。
- 指标绑定发布回执和账号，而不是绑定生成任务或平台名称。
- 标准化播放量、阅读量、点赞、评论、回复、收藏、分享、点击等指标。
- 平台不提供的指标记录为 `null`，并保留采集时间、来源、错误和重试信息。
- 账号更换、重新授权或删除后，历史报告仍指向原账号引用，不改写历史。
- Content Studio 只保存报告投影；不抓取未授权的私有后台。

验收：同一平台不同账号的报告可以分别查看；采集失败或指标不可用不会被写成零。

### M4：反馈读取与受限外部操作（对应 V0.6）

- 先做公开反馈读取、去重、分类和人工审核队列。
- 回复、删除或 Issue 路由必须同时满足：匹配项目策略、已知发布回执、最新反馈
  重读、支持的适配器和当前 Owner 授权。
- FAQ 只允许项目固定模板；敏感、法律、安全、隐私、支付、账号和含糊内容必须
  升级给人工，不自动回复。
- 每个外部写入都带账号引用、授权范围、幂等键和审计结果。

验收：任何评论内容都不能自行产生写入授权；适配器不支持时明确降级为人工处理。

### M5：适配器能力矩阵与维护机制（V0.6—V1.0）

- 为每个渠道声明文章、短帖、视频、图片、监测和人工辅助能力，而不是只返回一个
  “可用/不可用”。
- 为适配器定义版本、健康检查、配额/限流、重认证、失败分类和回执格式。
- 每个适配器都有无凭据契约 fixture、幂等测试、错误映射和升级回归测试。
- 先维护已有安全适配器，再按真实用户需求增加渠道；不为了“渠道数量”接入私有
  API、绕过验证、stealth 或任意浏览器脚本。
- 公开展示的渠道规格与实时授权状态分开，实时状态必须来自新鲜快照。

### M6：随 Content Studio 分发和诊断（对应 V0.6/V1.0）

- 安装器交付固定兼容版本，记录版本、安装来源和运行边界。
- `content-studio doctor` 检查 `marketing-ops` 是否安装、版本是否兼容、项目档案
  是否存在、渠道状态是否可读取；不打印凭据。
- 支持升级、回滚、日志摘要和安全卸载，不删除未知项目文件。
- Content Studio Plugin 只连接本地 MCP/应用服务；用户仍通过 `marketing-ops` 的
  官方本地交互流程配置渠道。
- 任何公共云入口都只做协调和元数据，不把账号授权或媒体生产搬到服务端。

验收：用户只安装 Content Studio 就能得到兼容的 `marketing-ops`，但必须主动完成
渠道配置；安装本身不会产生发布权限。

## Content Studio 版本映射

| Content Studio | `marketing-ops` 配套工作                             | 不提前做的事情                         |
| -------------- | ---------------------------------------------------- | -------------------------------------- |
| V0.3           | 定义客户端边界、假适配器、账号引用类型和回执校验接口 | 不连接真实渠道                         |
| V0.4           | 接收媒体校验和资源变体，验证发布包输入               | 不在合成器里实现发布                   |
| V0.5           | 状态快照、项目账号绑定、发布包、人工接管、回执、监测 | 不宣称多账号已可真实执行，未授权不写入 |
| V0.6           | 多账号正式契约、受限反馈、安装器、doctor、升级回滚   | 不自动登录、不绕过验证码               |
| V1.0           | 公共 Plugin 审核材料、稳定适配器矩阵和长期兼容策略   | 不让公网服务成为授权或媒体单点         |

## TDD 与安全停止线

每个阶段先写失败契约测试，再实现最小适配器或客户端。至少覆盖：

- 不同 `projectId`、活动、渠道和账号之间的数据隔离；
- 账号引用缺失、状态过期、策略不匹配和素材校验失败时 fail closed；
- 同一幂等键重试不会重复外部写入；状态不确定时先查询；
- 只有匹配成功回执才能进入 `published`，监测只能绑定该回执；
- 不支持的指标、渠道或动作显式返回 `unavailable`；
- 测试、日志和 MCP 参数不含密码、token、Cookie、浏览器 Profile 或付款信息。

以下事项永远不属于扩展计划：通用登录自动化、CAPTCHA/2FA 绕过、stealth、私有
接口、任意 Shell/Playwright 脚本、任意选择器、从内容或网页评论推断授权，以及未经
匹配 Owner 授权的发布、回复或删除。
