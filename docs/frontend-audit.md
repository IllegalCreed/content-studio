# 工作台前端审计

> 状态：V0.2 前端结构收口清单
> 审计日期：2026-08-03
> 范围：`apps/workbench/src` 当前代码，不把静态演示数据误认为运行时能力

这份审计解决一个实际问题：工作台必须让用户看清“总览 → 项目 → 发布活动 →
执行任务/活动产物”的关系，同时保持 Vue 只是控制面，不能在前端复制一套生产、
录制或发布引擎。

## 逐项审计结果

### 1. 信息架构与语义

- **符合规划**：左侧已经按“全局控制台 / 当前项目”分组；项目渠道账号在项目概览
  配置，活动只选择项目已启用渠道。
- **需要修正**：活动列表仍在同一个模板里同时承担列表和详情，容易让用户误以为
  活动只有一张“步骤卡”。活动详情应以独立路由为唯一主视图，列表只负责筛选、创建和
  进入详情。
- **需要修正**：页面标题、按钮和状态的来源没有统一放在页面组件中；目前同一业务对象
  的投影逻辑散落在 `WorkbenchApp.vue`、`model.ts` 和详情页。

### 2. 活动、任务、任务阶段

- 活动是业务对象，状态来自 `PublishingActivity.status`：`draft`、`planned`、
  `active`、`completed`、`archived`。
- 任务是执行记录，类型为制作、发布、监测，状态来自任务生命周期：
  `queued → generating → recording → composing → awaiting-owner → published → monitoring`，
  另有 `failed`、`cancelled` 终态/分支。
- `taskLifecycleProjection()` 已经根据持久化任务和事件生成任务阶段；静态演示任务的
  阶段仍在 `model.ts` 中固定，是演示数据，不是运行时引擎的事实。
- **UI 规则**：活动详情显示“活动状态”；任务面板显示“任务状态”和“任务阶段”。两者
  不再使用“活动步骤”这个叫法。

### 3. 状态与路由

- Pinia `workbench` store 已承接活动详情页的运行时刷新和视频计划操作。
- **尚未完成**：`WorkbenchApp.vue` 仍持有大量页面状态（选中活动、任务、素材、渠道、
  弹窗和错误），刷新后会丢失；筛选、选中项和任务范围也没有写入 URL。
- 下一步应把列表筛选写入 query，把活动/任务/素材/渠道选择写入 params 或 query，
  并让浏览器后退能恢复用户上下文。

### 4. 功能闭环

- 已闭环：项目渠道绑定 → 活动创建 → 视频计划版本/视口修订 → 活动详情确认 → 任务
  面板查看 → 本地任务取消/开始/录制/重试。
- 已闭环：活动产物预览 → 用户明确晋升为项目素材 → 清理预览。
- **未闭环**：AI 生成文章、图片、脚本的实际入口还未接入；发布计划目前只在内容卡片
  上有入口，发布/监测任务在所有活动场景下的自动创建还需要服务层补齐；活动报告仍
  缺少按渠道的时间线和指标详情。
- **明确边界**：任何“发布”按钮都只能进入本地发布准备或 owner handoff，不能直接写入
  真实渠道。

### 5. 组件与样式

- 已拆分：`AssetPreview`、`VideoJobPanel`、`StatusRail`、`SelectMenu`、活动详情页和
  Pinia store。
- **主要结构问题**：`WorkbenchApp.vue` 仍包含导航、布局、项目概览、活动列表、任务、
  渠道、素材、人工处理和报告全部模板，当前约 2200 行。这是维护和测试的主要瓶颈。
- **拆分顺序**：先抽 `WorkbenchShell`/导航，再抽活动列表、任务面板、渠道管理、素材库，
  最后删除旧的活动内嵌详情模板。
- 共享按钮、表单控件、下拉弹层和焦点样式应集中在基础样式/组件中；禁止页面各自复制
  字号、内阴影、箭头定位和禁用态。

### 6. 可访问性与交互基线

- 活动详情的运行时错误、加载和操作结果已经使用 `aria-live`。
- 待补：全局跳过链接、明确的主内容 landmark、导航使用链接语义、表单控件补充 `name`
  和合适的 autocomplete、所有焦点态统一使用 `:focus-visible`。
- 待补：素材图片预览补充尺寸/加载策略，视频和音频预览保留原生控件；长标题、长路径
  和错误消息需要稳定换行。
- 所有图标按钮必须有可读标签；导航是链接，改变状态才使用按钮。

## 收口顺序

1. **路由和详情（当前）**：保留 `/project/activities` 列表，所有活动卡片进入
   `/project/activities/:activityId`；补路由测试。
2. **状态集中化**：把 WorkbenchApp 的运行时快照、选择状态和异步错误迁移到 Pinia，
   页面只负责展示和事件派发。
3. **页面组件化**：抽共享壳、导航、活动列表、任务面板、渠道管理和素材库；删除
   内嵌活动详情，避免同一对象出现两套展示。
4. **闭环补齐**：补 AI 内容生成入口、发布安排/监测任务创建状态、按渠道报告详情；
   每个动作必须有成功、失败、只读演示和权限边界提示。
5. **视觉和交互门禁**：统一按钮、select popup、箭头、焦点、空状态、加载态和移动端
   响应式布局，再跑全量测试和生产构建。
