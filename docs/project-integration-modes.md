# 项目接入模式

> 状态：产品与制作架构决策
> 最近评审：2026-08-02

## 决策

Content Studio 不假设所有项目都能用同一种方式录制。项目在注册时必须声明接入
模式，当前分为两种：

```text
有源项目（source-owned）
  有源代码，可以为关键页面状态增加稳定标注，并注册项目适配器

无源项目（web-assisted）
  没有源代码，只能观察线上网页，由 AI 和浏览器辅助能力共同完成录制
```

两种模式都经过同一条业务流程：

```text
用户主题
  → AI 拍摄大纲
    → 渠道内容和资源规格
      → 项目录制计划或浏览器辅助计划
        → 用户确认
          → 录制任务
            → 预览、媒体素材和录制回执
```

AI 负责“拍什么、怎么讲、镜头如何组织”；项目接入层负责“页面如何进入、哪些
元素代表目标状态”；录制运行时负责安全执行和保留证据。

## 有源项目

有源项目是首选模式，Algorithm Visualizer 属于这一类。

### 项目需要提供什么

- 项目事实、规范 URL 和预览启动方式；
- 关键页面和演示场景；
- 关键按钮、状态容器和结果区域的稳定语义信息；
- 必要时增加少量 `data-testid` 标注；
- 如果默认声明式流程不够，再提供经过许可的项目适配器。

项目可以在清单的 `captureTargets` 中登记这些关键节点。每个目标只需要一个稳定
的业务 ID、用途（`control`、`state` 或 `result`）、双语说明和一个语义定位器：

```json
{
  "id": "animation-play",
  "purpose": "control",
  "label": {
    "zh-CN": "播放动画按钮",
    "en": "Play animation button"
  },
  "locator": {
    "by": "test-id",
    "value": "animation-play"
  }
}
```

`test-id` 必须使用小写 kebab-case；`role`、`label` 和 `text` 仍然优先。目标清单
只描述录制真正依赖的节点，不要求给所有 DOM 添加标注，也不接受 CSS/XPath 选择器。

不需要给每一个 DOM 都加 `testid`。只标注录制真正依赖的稳定节点，例如开始按钮、
动画状态、结果区域和下一步操作。优先使用 role、label、text 和可访问名称，
`testid` 用于语义不足但确实需要稳定引用的节点。

### 录制流程

1. AI 根据主题和项目事实设计拍摄大纲。
2. AI 根据项目的语义标注和渠道规格生成版本化录制计划。
3. 项目负责人审核大纲和计划。
4. Content Studio 将计划编译为 `VideoPlan`。
5. Playwright 只执行编译后的 `wait-for`、click、fill、press、wait 和 capture 动作。
6. 生成片段、预览帧、日志摘要和录制回执。

如果项目需要代码级控制，项目负责人必须明确许可。AI 可以在项目内起草或修改
一个已注册、经过评审的窄适配器，但不能通过 MCP 传入任意 Playwright 脚本、Shell
命令、选择器或环境变量。

有源模式的目标是高确定性：同一项目版本、同一录制计划和同一运行环境，应能安全
重放和重试。项目代码或关键标注变化后，录制计划必须重新验证。

## 无源项目

无源项目没有可修改的源代码，不能预先在页面里增加 `testid`，因此只能采用线上
网页辅助模式。

### 录制流程

1. 用户提供公开生产网页或明确的项目访问入口。
2. AI 观察页面可见内容和可操作状态。
3. AI 设计拍摄大纲，并生成一次性的浏览器辅助计划。
4. 用户确认关键步骤，必要时亲自完成登录、验证或风险提示。
5. 浏览器插件或宿主的 Computer Use 能力辅助完成页面操作和录制。
6. 结果标记为辅助录制，并记录页面版本、人工介入和失败原因。

无源模式不能承诺和有源模式相同的自动化程度：

- 页面改版可能导致计划失效；
- 每次重试可能需要 AI 重新观察页面；
- 某些步骤必须由用户现场确认；
- 录制结果的可重复性和可测试性较低；
- 不适合作为高频、无人值守的批量 Worker。

浏览器辅助能力不能自动处理登录、验证码、2FA、平台审核或最终发布点击，也不能
读取或保存密码、cookie、浏览器 Profile 或支付信息。遇到这些步骤必须进入人工
接管，并由用户在官方页面完成。

## 需要登录时的人机接管

“等待用户登录”可以作为录制流程的一部分，但用户输入必须发生在可见的浏览器
页面里，而不是 Content Studio 的表单、MCP 参数、录制计划或日志中。

安全流程如下：

```text
录制发现认证边界
  → 任务进入 awaiting-owner
    → 打开或保留可见的临时浏览器会话
      → 用户自行输入用户名、密码并完成验证码
        → 用户确认“已完成登录”
          → 录制器在同一临时会话继续执行非认证步骤
```

录制器不得读取或保存密码、Cookie、浏览器 Profile、键盘输入或认证页面截图。
人工接管只恢复当前任务，不产生渠道发布授权，也不能把认证步骤编译成可重放的
Playwright 动作。

有源项目可以在项目自己控制的本地或测试环境中提供 mock 登录、预置测试身份，或
仅在该环境关闭 CAPTCHA。这个开关必须由项目自身实现并受环境和访问范围限制；
Content Studio 不提供通用验证码绕过，也不修改生产环境的认证策略。

当前 V0.2 录制器遇到认证页面会 fail closed，尚未实现暂停、用户确认和继续录制。
该人机接管能力列入后续应用服务和任务引擎阶段；在此之前，登录页面不会被自动化
处理。

## 项目配置模型

项目注册时至少记录以下能力声明：

```text
sourceAccess: source-owned | web-assisted
captureMode: deterministic | assisted
adapterId?: registered project adapter
requiresHuman: boolean
repeatability: high | conditional | low
```

Content Studio 不应在任务运行中悄悄把有源模式降级为无源模式。模式变化需要新的
项目能力确认、重新生成录制计划，并在回执中记录。

当前项目清单已经可以显式声明 `sourceAccess`、`captureMode`、`repeatability` 和
关键节点 `captureTargets`。历史清单省略这些字段时仍按兼容规则解释为
`source-owned`、`deterministic`、`high`；声明 `web-assisted` 时不能同时声明
`deterministic`，避免把无源项目误当成可确定性重放的项目。

## 对任务和回执的影响

有源模式可以正常使用完整的：

```text
queued → generating → recording → composing
       → awaiting-owner → published → monitoring
```

无源模式仍使用相同任务和回执模型，但可能在录制前或录制中进入
`awaiting-owner`。回执必须额外记录：

- 接入模式；
- 项目或网页版本引用；
- 录制计划版本；
- AI 观察和人工介入是否发生；
- 可重复性等级；
- 失败和重新观察原因。

这样用户能区分“自动化录制成功”和“一次人工辅助录制成功”，报告也不会把两者
混为同一种生产能力。

## 实施顺序

1. 先在有源的 Algorithm Visualizer 上完成 `testid`/语义标注、录制计划生成和
   Playwright 重放。
2. 将 `sourceAccess`、`captureMode` 和可重复性写入项目模型与录制回执。
3. 再做无源网页的浏览器辅助技术验证，只使用无凭据的测试页面。
4. 无源模式稳定前，不把它作为默认后台 Worker，也不让它阻塞有源项目的自动化。

详细实现必须继续遵守[架构](architecture.md)中的适配器和安全边界。
