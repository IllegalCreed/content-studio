# 产品功能模块

> 状态：产品结构基线
> 最近评审：2026-08-09

## 结构原则

Content Studio 是以 AI 为主要创作者和流程协调者的 MCP App。Vue 工作台是
控制面，不是另一套生成、录制或发布引擎。

产品结构遵循以下原则：

1. 渠道平台在全局定义，项目选择启用并为每个渠道绑定一个唯一的项目账号；发布
   活动只选择项目已启用的渠道，账号由项目配置自动解析。
2. 素材默认归项目所有，不预设跨项目通用素材库。
3. 发布活动表达一次主题下要创作和发布的内容，不在活动内部把业务对象统称为
   “任务”。
4. 制作任务、发布任务和监测任务属于执行层。全局任务面板是跨项目投影，项目
   任务面板是同一批任务的项目内投影。
5. 活动是一个主题下的内容生产单元，不区分“视频活动”或“文章活动”。文章、图文、
   动态和视频是渠道成品类型；同一渠道可以在一次活动中选择多个形态。图片、封面、字幕、配音、背景音乐、脚本和视频片段等是
   活动素材或中间产物，按渠道规格组装成可发布成品。
6. 移动端、PC 端、横屏、竖屏和方形内容通过资源变体表达，具体需要哪些变体由
   渠道规格决定，不假设每个平台都固定存在两套资源。
7. 每个渠道发布结果独立记录回执和公开地址，监测绑定发布结果，而不是绑定
   内容生成任务。

## 三级业务主线

用户理解产品时，先看下面三层；任务、渠道和运行时是围绕这三层提供的执行和管理
能力，不另起一套业务层级：

```text
总览
└─ 项目
   └─ 发布活动
      ├─ 活动简报（主题、目标和时间范围）
      ├─ 目标渠道（账号由项目配置解析）
      ├─ 内容组和渠道内容
      ├─ 活动素材与中间产物
      ├─ 渠道成品与资源变体
      ├─ 制作、发布、监测任务
      ├─ 人工介入步骤
      ├─ 发布回执
      └─ 数据表现
```

- **总览**聚合多个项目的活动、任务、待人工事项和报告摘要。
- **项目**拥有项目事实、项目渠道绑定、项目素材和多个发布活动。
- **发布活动**先保存主题、目标和目标渠道，再组织内容规划、活动素材、渠道成品和
  发布结果；活动不在渠道选择时重复选择账号。
- 全局渠道目录、全局任务面板、安装与运行、能力与适配器属于跨项目控制能力。

## 渠道管理的实际工作内容

渠道管理不是一张“平台名称列表”，而是三层信息的组合：

1. **全局渠道规格**：平台支持哪些内容形态，以及每种形态的标题/正文长度、允许的
   媒体类型和媒体数量要求；同时登记可监测指标和交付方式（全自动候选、人工辅助、
   仅生成内容）。这些是跨项目可复用的能力定义。发布助手只包含全自动候选和人工辅助
   渠道；仅生成内容渠道只负责产出渠道内容包，不绑定 `marketing-ops` 账号、不创建发布任务。
2. **项目渠道绑定**：当前项目是否启用某个全局渠道，以及该渠道绑定的唯一项目账号。
   格式和交付方式来自全局渠道规格，在项目页只读展示，不在项目里再次选择。关闭项目渠道
   不会删除全局定义，也不能在活动里继续选择。
3. **发布助手状态**：从 `marketing-ops channels_status` 读取的只读快照，包括账号别名、
   适配器是否就绪、需要重新授权/被阻塞的原因和可监测指标。它只说明当前
   能力，不能单独证明发布权限。

全局渠道详情页应因此支持“选中渠道 → 查看全局账号和项目引用数 → 查看格式限制 →
查看助手健康和下一步 → 查看可监测指标”的闭环。项目开关和项目账号只在项目渠道配置
中查看和修改。尚未读取到快照的渠道要显示“未查询”，不能把本地项目配置当成健康或授权
状态。活动选择渠道时只能从项目已启用的渠道中选择；
发布任务再根据活动内容和渠道交付方式解析项目账号，进入自动候选或人工辅助流程；
仅生成内容渠道在保存内容后结束，不允许创建发布安排。

### 渠道账号的归属和唯一性

全局渠道目录只描述平台能力，不提供项目账号选择。Content Studio 当前采用“项目内每个
渠道一个唯一账号”的模型，账号身份通过项目渠道绑定引用 `marketing-ops` 的授权边界。
当前 `channels_status` 仍主要按渠道返回一个脱敏身份，发布包和回执的账号引用契约尚未
完整落地；工作台中的账号展示不能被当成真实发布能力。

“渠道”指平台，“渠道账号”是项目在该平台上的身份。例如外部授权系统可以管理多个
X 账号，但同一个项目在当前版本只能绑定其中一个 X 账号。不同项目可以绑定不同账号，
账号不会因为渠道名称相同而自动共享。

- `marketing-ops` 可以在自己的授权边界管理平台账号；Content Studio 只保存项目绑定所需
  的不透明引用、脱敏别名和状态，不保存密码、token、cookie 或浏览器 Profile。
- 这里的“授权边界”不等于 Content Studio 的业务项目：`marketing-ops` 只维护账号、
  渠道策略、外部操作和回执，不创建或管理项目、活动、素材和制作任务。
- 项目渠道绑定的唯一性约束是 `(projectId, channelId)`；项目可以绑定多个不同渠道，
  但同一渠道不能同时绑定两个活动可用账号。
- 活动只保存目标渠道，不保存账号选择；任务、发布安排和监测记录根据项目绑定解析
  账号，并在需要审计时保存当时的账号引用或绑定版本。
- `marketing-ops` 负责账号实际授权和健康检查；Content Studio 只显示项目范围的
  脱敏快照。账号是否能被其他项目使用，必须由各项目明确建立自己的绑定，不能从一
  个项目的活动配置中推断。

因此全局页面管理“平台和账号目录”，项目页面管理“本项目启用哪些渠道及每个渠道的
唯一账号”，活动页面只管理“本次主题使用哪些渠道”。

2026-08-02 的工作台演示使用 Algorithm Visualizer 的只读状态检查：GitHub、Bluesky
和 Mastodon 显示已就绪，DEV 显示需重新授权，微博显示已阻塞；Bilibili、YouTube、
知乎和 X 是项目活动中的人工辅助目标，尚未读取到本地 `marketing-ops` 快照，因此显示
为“未查询”。演示不执行发布、不保存凭据，也不把这些状态写回渠道配置。

## 产品术语

| 中文产品术语 | 当前代码兼容名      | 含义                                                                       |
| ------------ | ------------------- | -------------------------------------------------------------------------- |
| 项目         | `Project`           | 事实、渠道选择、制作方式、素材和活动的归属边界                             |
| 发布活动     | `Campaign`          | 围绕一次主题、目标或时间窗口组织的多渠道内容集合                           |
| 渠道账号     | `channelAccountRef` | 某个渠道平台上的具体账号身份；同一项目每个渠道唯一绑定                     |
| 内容组       | —                   | 活动内共享一个观点或叙事目标的一组渠道内容                                 |
| 渠道内容     | —                   | 为某个具体渠道和内容形态创作的文章、图文、动态或视频，不要求各平台正文相同 |
| 资源变体     | —                   | 面向设备、画幅、分辨率或渠道格式的具体文件                                 |
| 渠道授权人   | `Owner`             | 有权在官方渠道界面完成登录、验证、审核和最终点击的人                       |
| 人工接管     | `Owner handoff`     | 系统把必须由渠道授权人完成的步骤安全移交给人工                             |
| 发布记录     | publication/receipt | 一次具体渠道发布的结果、公开地址和发布回执                                 |
| 数据快照     | observation         | 某个发布时间点之后采集到的一组标准化指标                                   |

产品界面和面向用户的文档统一使用中文术语。为保持 V0.1 数据和 API 兼容，
内部可以暂时保留 `campaignId`、`ownerHandoff` 和 `awaiting-owner` 等名字，
后续通过版本化契约演进，不做无迁移的直接改名。

## 活动与任务的边界

活动页面使用业务语言：

```text
发布活动
  → 内容组
    → 渠道内容（文章、图文、动态或视频）
      → 资源变体
      → 发布安排
        → 发布记录
          → 数据快照
```

活动的创建顺序固定为“先主题，再渠道，再内容和制作”：

```text
活动主题、目标和时间范围
  → 选择项目已启用的渠道
    → 按渠道规格规划内容
      → 生成或导入活动素材
        → 将素材组装为渠道成品
          → 安排发布、人工确认和回执
            → 按发布回执建立监测
```

活动素材和渠道成品不是同一个对象。脚本、文章草稿、图片、封面、字幕、配音、背景
音乐、视频片段和预览帧可以作为素材或中间产物；渠道成品是包含标题、正文、媒体、
资源变体和渠道元数据的可发布内容包。一个素材可以被同一活动的多个渠道成品引用，
但每个渠道成品可以根据渠道规格使用不同的组合和版本。

执行层根据这些业务对象创建任务：

```text
渠道内容或活动产物 → 制作任务
发布安排           → 发布任务
发布记录           → 监测任务
```

活动不包含一个名为“任务”的业务栏目。全局和项目任务面板只是对执行记录的
不同范围投影，不能成为另一份数据源。

### 任务内部步骤

制作、发布、监测是三种执行任务大类。一个任务内部可以继续有多个可观察步骤，
但不把每一个步骤都提升成全局任务：

```text
视频制作任务
├─ 生成脚本和拍摄大纲
├─ 生成分镜和录制计划
├─ 浏览器录制
├─ 生成预览帧
├─ 人工检查（需要时）
├─ 合成视频
├─ 字幕和旁白
└─ 生成渠道要求的资源变体
```

任务详情必须同时显示：所属项目、所属发布活动、关联内容、目标渠道、当前步骤、
步骤进度、尝试历史、日志摘要、预览和已登记产物。只有确实需要独立排队、取消或
重试的工作，才在未来拆成子任务；否则使用统一任务事件和阶段记录。

## 素材归属

V0.2 不设置全局通用素材库。

- 项目素材可被同一项目内的多个活动引用。
- 活动产物默认归所属活动所有。
- 项目素材库是可管理的真实文件集合，不是一个数量统计；总览可以显示数量，项目
  素材页必须提供列表、预览、版本、来源、引用关系、保留状态和清理预览。
- 活动页分别展示“引用的项目素材”和“本次活动产物”，不能把两者合并成活动素材库。
- 有复用价值的活动产物可以由用户显式沉淀为新的项目素材版本，并保留来源。
- 跨项目共享以后通过显式的品牌空间或素材集合解决，不预先把项目素材暴露为
  全局资源。
- 用户显式保存的项目素材、最终产物和发布回执默认长期保留；草稿、失败尝试、旧
  预览和中间产物按保留期限清理。
- 清理由本地运行时提供占用统计、清理预览、回收区和恢复窗口，不要求用户手动
  删除文件，也不会删除未登记的项目文件。

### 统一素材预览能力

素材预览是项目素材库和活动产物的共同能力，不再为录制视频、项目图片和文章内容
分别设计临时入口。预览必须基于已经登记的项目/活动素材 ID，由应用服务解析安全的
受控文件引用；前端不能提交任意本地路径。

- 文章版本、脚本和字幕：提供纯文本/Markdown 阅读视图，并显示版本、来源和校验和。
- 图片、封面和预览帧：提供缩略图、放大查看和图片尺寸信息。
- 视频片段和最终视频：提供带控制条的播放器，同时保留下载入口、时长、画幅和校验和。
- 音频、旁白和背景音乐：提供带控制条的播放器、时长和音频格式信息。
- 不支持或文件缺失：显示“不可预览/文件缺失”原因，不伪造成功状态。
- 所有预览都必须校验 `projectId`、素材/产物 ID 和版本归属，禁止通过相对路径越权读取。

当前首版已经接入：运行时为已登记的活动产物和项目素材提供项目范围的预览接口，工作台
会按素材类型显示文字阅读、图片、视频或音频预览，并提供登记文件下载入口；活动里的文章
成品也可以直接展开文字预览。预览文件只从配置的本地 production output root 读取，并用
项目 ID、素材 ID 和真实路径归属做校验。素材页同时提供只读占用统计和清理预览，只列出
已登记文件，不会扫描或删除未知文件；用户可显式确认把活动产物移入回收区，并在恢复
窗口内单项恢复。项目素材默认受保护，自动按期限清理仍待补齐。

## 人工介入与渠道授权人

人工介入不是和项目、发布活动平级的业务模块，而是任务执行过程中按需出现的步骤。
例如项目预览录制需要用户登录测试环境、发布需要渠道授权人登录官方平台、完成
验证码、审核内容或点击最终发布按钮。

任务进入 `awaiting-owner` 时，控制面显示一张人工处理卡片，包含所属项目、发布活动、
关联内容、原因、官方目标地址、检查单、失效时间和完成结果。用户在官方页面中完成
登录和验证，敏感输入不进入 MCP 参数、录制计划、日志或回执。

总览和任务面板可以提供“待人工处理”筛选，用于聚合这些记录；活动详情仍是查看
具体上下文和继续执行的主要位置。发布场景的 `OwnerHandoff` 继续作为发布安排的
审查包，其他制作场景的人工介入以后通过通用任务步骤契约扩展，不把它们混成一个
独立的内容模块。

## AI 的介入范围

AI 是主要创作者和流程协调者，可以通过受约束的 MCP 能力：

- 读取项目事实、活动简报和渠道规格；
- 制定内容方向和渠道组合；
- 生成、修改和比较文章；
- 生成图片方案、提示词、图片和封面；
- 生成视频脚本、分镜、录制计划、字幕稿和旁白稿；
- 为不同渠道和资源规格生成独立版本；
- 启动、取消或重试制作任务；
- 根据审核意见修订内容；
- 读取发布回执和监测数据并形成复盘。

交互式创作由 MCP 主机中的 AI 发起。定时或长时间运行的自动创作需要后台 AI
执行器承接，但必须使用相同的项目上下文、版本化契约、任务事件和审计边界。
Content Studio 不在项目文件、MCP 参数或产物中接收或保存模型和渠道凭据。

AI 生成内容不等于获得发布权限。所有真实渠道写入仍由具有匹配授权和策略的
`marketing-ops` 执行，或者在官方平台界面中由渠道授权人完成。

## 项目内对接

项目先选择一种接入模式，再选择具体制作方式：

1. **有源项目。** 对关键 DOM 增加少量 `testid`/语义标注，使用 AI 生成的录制
   计划和 Playwright 确定性执行；复杂项目可以增加受信任的窄适配器。
2. **无源项目。** 不修改目标网页，由 AI 观察页面，通过浏览器插件或宿主 Computer
   Use 辅助操作和录制；可重复性较低，必要时由用户现场介入。
3. **导入已有产物。** 直接登记已经生成的文章、图片、音频或视频。

AI 可以根据主题先生成拍摄大纲，再生成项目录制计划或无源网页辅助计划。第二种
模式不能保证同有源模式一样的自动重放，也不能把任意脚本、Shell 命令或选择器
作为 MCP 输入传给 Content Studio。适配器必须按 ID 注册、接受
版本化参数，并遵守语义定位和无凭据边界。

### 录制器配置能力扩展

当前录制器根据活动视频格式使用固定画幅预设：横屏 1920×1080、竖屏 1080×1920、
方形 1080×1080。这个尺寸同时作为目标网站的 Playwright viewport 和录制视频尺寸。
活动视频计划现在也可以覆盖一组安全的自定义宽高；系统会校验最小/最大边长、总像素、
宽高比例和横竖方形方向，防止把录制器变成任意浏览器参数入口。

后续配置按以下层级合并，越具体的设置只能覆盖允许的字段：

1. **项目默认值**：项目的默认 viewport、确定性浏览器环境和录制安全策略。
2. **活动拍摄计划**：本次主题的基础画幅、经过校验的网站 viewport、输出媒体尺寸和计划版本。
3. **渠道资源变体**：按渠道、移动端/PC 端或平台规格生成不同画幅和分辨率的成品。
4. **单次执行参数**：仅允许有限的超时、尝试次数和取消策略，不允许临时注入脚本、
   任意浏览器参数、cookie、凭据或浏览器 Profile。

当前已开放的安全字段包括项目默认值和活动视频计划中的 viewport、输出媒体宽高、
device scale factor、语言/色彩环境。viewport 表示网站看到的 CSS 像素尺寸，输出媒体
尺寸表示最终文件像素尺寸；两者可以不同。帧率、码率、裁切、转场和响度属于后续
FFmpeg 合成器，不由当前 Playwright 录制器直接决定。

工作台新建活动时可以选择建立视频制作计划，并默认使用当前项目已登记的拍摄流程；在
活动详情中修改宽高会产生新的活动版本，旧的确认自动失效，用户需要再次确认新计划。
活动修订接口只接受主题、视频计划和版本号等明确字段，不接受浏览器启动参数、脚本或
选择器。

所有自定义尺寸必须经过正整数、最大边长、总像素和比例校验，并保留最终生效配置到
编译后的拍摄计划；录制回执会记录完整配置和计划版本，确保重试和审计可复现。没有
自定义配置时继续使用三种固定预设。当前白名单只允许 device scale factor 1/2、项目
声明过的 locale，以及 dark/light/no-preference 色彩环境；不允许通过配置注入浏览器
启动参数、脚本、选择器、cookie、凭据或浏览器 Profile。

## 发布与监测

每个渠道发布安排最终形成独立发布记录。只有匹配的 `marketing-ops` 回执才能
让对应记录进入“已发布”。

监测计划绑定发布记录和公开地址，可以按渠道能力安排 1 小时、48 小时、7 天
或项目自定义时间点。标准指标包括播放量、阅读量、点赞、评论、回复、收藏、
分享和点击。平台不提供的指标记录为 `null`，不能用 `0` 伪造。

指标来源只允许是公开数据、授权适配器结果或渠道授权人的明确录入。Content
Studio 展示和汇总结果，不抓取未授权的私有后台，也不在本仓库执行渠道回复、
删除或其他外部写入。

## 安装与运行边界

Content Studio 是开源、本地优先的完整产品。普通用户通过统一安装器获得 core、
工作台、本地 MCP、制作 Worker 和固定兼容版本的 `marketing-ops`，只需安装一个
Content Studio Plugin。

`marketing-ops` 的随附安装只解决依赖交付，不改变模块所有权：渠道配置、授权、
真实写入和发布回执继续由它独立负责。未配置渠道时，项目、活动、AI 创作和本地
制作功能仍然可用。

公共 Plugin 使用轻量公网 MCP 入口满足目录审核和宿主访问，本地自托管不依赖该
入口。详细分发决策见
[开源、本地优先与安装分发](local-first-distribution.md)。
