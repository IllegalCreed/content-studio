# 工作台前端产品审计

> 状态：V0.2 收口记录
> 审计日期：2026-08-03
> 依据：`product-vision.md`、`product-modules.md`、`architecture.md` 与当前源码
> 范围：`apps/workbench/src`、本地 runtime API 和 core 类型

这份审计只回答一个问题：连上本地运行时后，用户能不能看懂并完成一次“主题 → 内容 → 制作 → 发布交接 → 回执 → 监测”的工作。页面是控制面，不能在浏览器里复制 AI、录制、合成或真实渠道发布引擎。

## 当前结论

工作台已经不是介绍页：活动、任务、渠道绑定、活动产物、项目素材、发布回执和监测报告均有真实 runtime 投影，且演示数据只在 runtime 不可用时使用。

本轮收口范围：

- 修正文档中已经过时的“任务步骤硬编码”“报告没有时间线”“人工页完全不能操作”等结论。
- 增加 owner handoff 的“已完成/取消”本地写操作；完成只记录授权人已完成交接，仍等待 marketing-ops 回执，不代表自动发布成功。
- 将活动详情的“渠道结果”和“活动业务进度”移到纯投影模块，页面只展示。
- 在素材投影中传递 runtime 已登记的 SHA-256 校验和；预览组件继续显示图片尺寸、视频画幅/时长和音频时长，文件缺失仍显示错误。
- 保留 AI/MCP 的明确入口说明，但不伪造本地 AI 生成能力。

## 三层语义必须保持清楚

1. **活动**是业务对象，状态为 `草稿 / 已规划 / 进行中 / 已完成 / 已归档`。
2. **任务**是执行记录，分为制作、发布、监测；一个活动可以关联多个任务。
3. **任务阶段**是单个任务的运行生命周期：`排队中 → 生成中 → 录制中 → 合成中 → 等待人工 → 已发布 → 监测中`，另有失败和取消分支。活动详情显示活动业务进度，任务面板显示任务阶段，不能把两者叫成同一组“活动步骤”。

## 已落地的产品闭环

- 项目渠道绑定 → 活动创建 → 内容组/渠道内容 → 视频计划确认与视口修订。
- 制作任务 → 本地录制/日志/预览帧 → 取消或重试。
- 发布安排 → publication 任务；发布 receipt → published 状态并创建 monitoring 任务。
- owner handoff → 授权人完成或取消交接记录；后续仍由 marketing-ops receipt 决定发布结果。
- 活动产物预览 → 用户明确晋升为项目素材 → 清理预览。
- 发布报告 → 最新指标、按渠道采集时间线、数据来源和公开地址。

## 尚未伪装成已完成的能力

- **AI 正式创作入口**：当前 UI 只能保存用于验证 runtime 合同的内容。正式文章、图片、视频脚本和拍摄大纲由 MCP 主机调用，前端不复制生成引擎。
- **真实渠道写入**：任何按钮都不会因为“完成交接”而获得发布权限；需要独立 marketing-ops 授权与回执。
- **素材管理深度**：当前 runtime 的 `ProjectAsset` 有登记路径和 SHA-256 校验和；文件大小、格式识别和自动保留期限仍待补齐。活动产物的显式回收、预览指纹和恢复记录已经进入 Runtime 契约。
- **多项目总览数据源**：工作台总览和全局任务页已经按跨项目语义展示，并明确标注“已接入项目”数量；当前 runtime 仍只有单项目读取接口，不能把单项目示例数字伪装成完整跨项目聚合。下一步需要项目注册表/全局汇总接口。
- **视觉门禁**：统一按钮、select popup、箭头、焦点、长文本换行、加载/空/错误态需要在结构收口后做一次集中验收。

## 后续路线

V0.2 以“可观察、可取消、可重试、可交接、可报告”为收口标准；下一阶段再接 MCP AI 正式创作入口、storage 元数据/回收策略、报告趋势与导出，以及多项目注册表。任何新增页面都必须复用现有路由、Pinia、投影模块和 runtime 契约，不在 `App.vue` 里重新堆业务逻辑。
