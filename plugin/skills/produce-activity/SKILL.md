# 制作发布活动

先完整读取 [活动制作工作流](references/workflow.md)，再调用工具。不要从活动简报直接跳到
制作或发布。

## 以 Agent 对话驱动审稿

- 先调用 `get_project_view`，以持久状态中的 `projectId`、版本和任务为准；不要依赖对话记忆
  猜测进度。
- 把脚本、正文、分镜和修改摘要直接展示在 Agent 对话中，请用户逐版反馈。
- 每次修改保存为新版本并回到待确认；只有用户对当前精确版本明确确认后才越过确认门。
- MCP 保存版本、确认、任务、产物和交接；Workbench 只投影这些状态，便于随时查看，
  不把“看过页面”当作确认。

## 分开内容、制作与发布

- 图文先审正文和引流目标，再审卡片计划与最终排版。
- 视频先审视频脚本，再审分镜；按分镜分段录制，错误时只重录对应片段，最后再合成、
  加字幕、配音并生成封面。
- 未实现或未配置的字幕、配音、生成器或录制能力必须明确标为阻塞，不得伪装成已完成。
- 内容和成品确认完成前，不得创建发布计划。
- 用户审核最终图文或视频后，用 `confirm_channel_content_production`
  确认当前成品版本；这与 `confirm_channel_content` 的文案/脚本确认是两个门。
- 进入渠道登录、验证码、最终发布确认或发布回执阶段时，转用 `review-and-handoff`。

## 处理等待与失败

- 用 `list_project_tasks` 和 `get_task` 查看追加式事件。
- `input_required` 表示停止自动推进并向用户说明需要确认的精确对象。
- 失败先定位原因，再用 `retry_task` 创建新尝试；不要并发重复启动同一任务。

## 边界

本 Skill 不授予渠道发布权限，不接收凭据，也不替用户点击最终发布。外部写仍需要与当前
活动匹配的独立授权和 Owner 人工接管。
