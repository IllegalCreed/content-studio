# 活动制作工作流

把下面八个阶段当作业务状态门，而不是一串可以一次性跑完的工具调用。Agent 对话是创作、
修改和确认的主入口；MCP 是持久状态与受控能力边界；Workbench 是只读进度和产物投影。

## 1. 活动简报

1. 调用 `get_project_view` 获取项目事实、现有活动和任务。
2. 与用户确认活动目标、受众、渠道、内容形式、核心主张、站点引流目标和成功指标。
3. 调用 `create_publishing_activity` 保存活动简报。
4. 此阶段不得启动制作任务或建立发布计划。

完成条件：用户认可活动方向，活动仍没有被当作渠道成品。

## 2. 内容草案

为每个内容形式先形成可读草案，再调用 `save_activity_content_pack` 或
`save_channel_content` 保存首个版本。

### 图文草案

至少展示并讨论：标题、开场、核心论证、项目或产品价值、站点链接与行动号召、卡片/配图
提纲。介绍项目时，算法知识服务于用户理解产品，不能退化成与项目无关的纯科普。

### 视频草案

先给出视频脚本，不录制。脚本至少包含：开场钩子、逐段旁白、画面意图、网站演示动作、
转场和行动号召。让用户直接在 Agent 对话里提出删改意见。

完成条件：所有目标形式都有持久化草案，但仍是待确认状态。

## 3. 内容确认

1. 调用 `revise_channel_content` 把反馈写成新版本；列出相对上一版的修改摘要。
2. 修改正文、标题、链接、镜头意图或媒体后，把确认状态重置为待确认。
3. 分别请求用户确认当前精确版本；用户明确同意后调用 `confirm_channel_content`。不得用
   “用户查看了 Workbench”推断确认。
4. 当前 MCP 若缺少版本修订或确认能力，停止并报告能力缺口，不要在记忆中假装已确认。

完成条件：每个要继续制作的渠道内容版本都取得明确 Owner 确认。完成前不得创建发布计划。

## 4. 制作计划

### 图文

根据已确认正文确定卡片顺序、每张图的信息目标、文案与图片对应关系、封面和最终排版。
媒体计划改变内容含义时，退回内容确认。

### 视频

仅在视频脚本确认后建立分镜和拍摄计划。每个分镜记录：目标、旁白、页面/画面动作、预计
时长、输入与输出状态，以及可以独立重录的边界。调用 `get_activity_video_plan` 读取版本化
计划并让用户单独确认；用户明确同意后调用 `confirm_activity_video_plan`。项目页面录制还
必须先完成 DOM-first 调研。

完成条件：制作计划与已确认内容版本绑定，分镜边界足以支持单段重录。

## 5. 分段制作

1. 调用 `start_production_task` 启动已经越过确认门的任务。
2. 视频逐分镜生成独立 clip；每段完成后检查画面、动作、旁白和时长，只重录失败片段。
3. 片段全部通过后再拼接，随后处理字幕、配音、音量、转场和封面。
4. 图文按卡片计划生成或登记媒体，再检查顺序、裁切、可读性和正文对应关系。
5. 用 `list_project_tasks`、`get_task` 跟踪事件；缺少字幕、配音或生成能力时保持阻塞状态。

完成条件：所有组成产物可追溯到内容版本和制作计划，且不存在未处理的失败片段。

## 6. 成品确认

在 Agent 对话中展示成品清单、预览入口、版本和修改摘要，让用户审核完整图文排版、最终
视频、字幕、配音和封面。任何成品修改都会生成新版本并重新等待确认。用户明确
同意后调用 `confirm_channel_content_production`。Workbench 可以平铺
成品并提供详情入口，但只投影 MCP 状态。

完成条件：用户明确确认当前成品版本。完成前不得创建发布计划。

## 7. 发布协作

转用 `review-and-handoff`。建立发布计划前重新验证内容与成品确认；随后刷新渠道状态、验证
发布包、取得当前活动的独立授权，并在登录、验证码、风控和最终发布按钮处交给 Owner。
发布成功必须以严格匹配的渠道回执为准。

完成条件：取得可验证的发布回执，或清楚记录 Owner 尚未完成的接管动作。

## 8. 监测复盘

只对已有回执的作品建立监测。记录可验证的浏览、互动和可用性结果；采集契约尚未审定时
返回 unavailable。把结果与活动目标比较，形成复盘和下一版内容建议，不自动触发新发布。

## 恢复规则

- 每次继续活动都先读 MCP 持久状态，再决定停在哪个门。
- 只恢复与同一 `projectId`、`activityId`、内容版本和任务/交接标识匹配的流程。
- 发现未知状态、版本冲突、异步弹窗或缺少确认时 fail closed，并把需要用户处理的单一动作
  说清楚。
